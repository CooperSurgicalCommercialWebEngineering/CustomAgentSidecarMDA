Meet Agent Sidecar

A reusable Power Platform capability that places the right Copilot Studio agent beside the right record or list in a Dataverse model-driven app - without asking users to leave the work they are doing.

Guide aligned to Agent Sidecar Core 1.0.0.25
View source repository ↗

1. Understand the product

Agent Sidecar turns a published Copilot Studio agent into contextual help that feels native to Dynamics 365 and other Dataverse model-driven apps.

In contextRecord, view, and split-view awareness at the moment the user asks.
PersistentIndependent conversations remain available while users navigate.
ReusableOne Core solution supports multiple apps, tables, forms, and agents.

For application users

Ask for explanations, summaries, guidance, or list analysis without copying record data into another tool or losing the current screen.

For administrators

Discover apps and published agents, choose exact forms, select the visible icon, deploy, validate, edit, reconcile, disable, or uninstall a sidecar from a guided administration experience.

For makers

Reuse a consistent launcher, delegated identity model, conversation store, context contract, and release artifact instead of rebuilding an embedded assistant for every app.

For governance teams

Keep authorization user-scoped, persist only display-safe conversation text, separate distinct write-consent requests, and preserve explicit release controls.

2. Capability inventory

The Core package combines a polished administration app with a secure, context-aware runtime.

Multiple sidecars per app

Run up to ten enabled configurations in the same model-driven app. Each configuration GUID is a distinct pane identity; the app ID is only a grouping key.

Published-agent discovery

Select from published Copilot Studio agents in the environment. Standard and GitHub Copilot harness endpoints are inferred from the agent connection.

Precise placement

Choose the tables and individual main forms where each pane appears. Existing sidecars can update placement in place.

Configuration-specific icons

Use the selected agent's icon, upload a validated PNG or JPEG, or keep the packaged default. The dashboard shows the same configured icon users see in the app.

Record and split-view context

Resolve the active record immediately before a user action, including a record opened beside a list. Current-record context wins only when table, record, and form identities agree.

Explicit list analysis

When a user asks about a list, require a scope choice: Current view or All accessible records. Direct-list-first initialization is intentionally not supported.

Durable conversations

Resume real Agents SDK conversations, replay display-safe transcripts, exclude greeting-only sessions, and allow users to delete their own saved conversations.

Navigation-local context

Navigation updates local context only. It never sends an agent activity, creates a conversation turn, or produces an unsolicited response.

Unsupported-entity collapse

On a table not configured for the pane, the sidecar collapses on the rail without deleting its conversation or state.

Consent integrity

Repeated decisions for the same connector-consent request are deduplicated. Distinct write-consent requests remain separate and are never silently approved.

Guided administration

Create, edit, validate, reconcile, disable, re-enable, or uninstall one configuration at a time with progress feedback, concurrency protection, verification, and rollback.

Positive progress feedback

Long-running saves explain the work in progress and report completed steps with checkmarks so administrators can see successful progress.

3. Architecture and safety boundaries

A lightweight launcher, configuration-owned pane, and Dataverse-backed conversation store work together without introducing a separate web server.

Model-driven formA shared, reference-counted launcher resolves matching configurations.
Sidecar paneLoads one immutable configuration identity and current local context.
Copilot StudioMicrosoft 365 Agents SDK connects as the signed-in user.
DataverseStores configuration and bounded, display-safe conversation history.
BoundaryCurrent contract
IdentityMicrosoft Entra delegated authorization code flow with PKCE. No browser client secret and no token-broker dependency.
Pane identityThe configuration GUID is immutable pane identity. The model-driven app ID is a non-unique grouping key.
ContextThe launcher writes navigation context locally. The pane reads fresh context only for an explicit user action or new conversation.
Conversation dataUser-owned Dataverse rows retain Agents SDK conversation IDs and bounded user-visible text - not tokens, trusted context envelopes, full channel data, or connector payloads.
ConsentOnly duplicate callbacks for the same request are coalesced. Distinct requests remain distinct; there is no AdminConsentBypass.
Generated artifactssrc/generated/, bundled web resources, solution projections, and packaged Code App files are generated or maintained projections, not editing surfaces.
Behavioral invariantsDo not reintroduce proactive navigation or context events, auto-approve distinct MCP write requests, collapse configuration identity into app identity, or add a browser client secret.

4. Install and operate Agent Sidecar

The checked-in Core package is the deployable capability. Configuration happens through the packaged administration app.

  1. Import Agent Sidecar Core.

    Download AgentSidecarCore.zip and import it through Power Apps Maker Portal ↗. Core 1.0.0.25 is the current repository package.

  2. Grant runtime access.

    Assign the packaged Agent Sidecar User role alongside each user's normal application role. Administration remains restricted to System Administrators.

  3. Create a sidecar.

    Open the Agent Sidecar administration app, choose a model-driven app, select exact tables and forms, choose a published agent, review inferred identity details, select an icon, and deploy.

  4. Verify the target app.

    Open a configured form in the ordinary model-driven app shell, select the pane icon, sign in if prompted, and confirm that a question about the current record returns the expected record.

  5. Manage in place.

    Use the dashboard and sidecar overview to change placement or appearance, validate health, reconcile approved drift, disable or re-enable a pane, or uninstall only the selected configuration.

Defaults reduce setup workThe administration experience infers known application, environment, tenant, agent connection, and icon information wherever the platform exposes it. Review inferred values instead of retyping them.
Agent icon updates are copied, not linkedIf a published agent's manifest icon changes, edit the sidecar's Appearance, choose a different icon, reselect the agent logo, save, then refresh or reopen the model-driven app. A retained pane may need to be closed and recreated before the rail icon changes.

5. Style the maintained source safely

The runtime is divided so visual changes can remain visual. Use source control as the record of intent.

  1. Clone and branch.
    git clone https://github.com/martycarreras-psnl/CopilotStudioAgentMDA.git
cd CopilotStudioAgentMDA
git switch -c feat/your-brand-sidecar
pnpm install
  2. Change the sidecar shell.

    Edit model-driven/webresources/maftagsc_/copilot/agentSidePane.template.html for theme variables, toolbar, cards, spacing, loading/sign-in/error states, responsive layout, and focus treatment.

  3. Change Web Chat presentation.

    Edit only the presentation-focused styleOptions in model-driven/webresources/maftagsc_/copilot/agentSidePane.ts for message bubbles, nubs, composer controls, suggested actions, typography, and spacing.

  4. Change administration presentation separately.

    Administration pages and components live under src/pages/ and src/components/. Preserve Fluent UI v9, the three-layer architecture, and existing service/provider contracts.

  5. Regenerate projections.

    Run the maintained build. Never paste a visual edit directly into generated HTML, a solution projection, or the Core ZIP.

Template owns

  • Corporate design tokens
  • Header and toolbar
  • Loading, sign-in, and error states
  • Layout, borders, and shadows
  • Responsive and focus styling

Web Chat options own

  • Agent and user bubbles
  • Bubble tails and radii
  • Composer and send button
  • Suggested action pills
  • Conversation spacing and typography

Administration UI owns

  • Dashboard and overview hierarchy
  • Creation and editing workflows
  • App, form, agent, and icon selection
  • Progress, success, and error feedback

Do not mix into styling

  • Authentication and token handling
  • Configuration or context resolution
  • Conversation persistence
  • Consent decision behavior
Never edit generated assets as sourceDo not hand-edit model-driven/.../agentSidePane.html, agentSidePane.js, projected copies under solution/WebResources/, src/generated/, or packaged files inside solution-core/AgentSidecarCore.zip.

7. Build and validate locally

Use focused tests while iterating, then run the complete release gate before packaging.

Sidecar runtime

pnpm run typecheck:model-driven
pnpm run build:model-driven
pnpm run test:model-driven

Administration Code App and complete repository

pnpm run typecheck
pnpm test
pnpm run lint
pnpm run build
git diff --check

The model-driven build bundles MSAL and the Agents SDK into agentSidePane.html, compiles the shared launcher, and synchronizes maintained solution projections. Tests protect generated-file consistency, package integrity, delegated auth, context behavior, conversation and consent safeguards, and packaged Code App bytes.

Local preview has limitsA local preview can confirm static layout. Authentication, Dataverse context, app/form resolution, and the Copilot Studio connection must be tested in a model-driven app in a development environment.

8. Test safely in development

Use a dedicated development environment for visual iteration and runtime smoke tests. Confirm the target before every mutation.

  1. Confirm the development target.
    pac org who --environment https://YOUR-DEV-ENVIRONMENT.crm.dynamics.com
  2. Build before upload.

    Run the model-driven typecheck, build, and tests. Upload only generated output that corresponds to maintained source.

  3. Publish the development web resource.

    In Power Apps Maker Portal ↗, select development, open Solutions → AgentSidecarCore → Objects → Web resources, upload the generated agentSidePane.html and/or agentSidePane.js that changed, save, and publish.

  4. Refresh retained panes deliberately.

    Close and recreate a retained sidecar pane after a versioned web-resource change, then hard-refresh the model-driven app. A retained pane can otherwise continue using an older URL and icon.

  5. Smoke-test the full boundary.

    Check visual states, keyboard and zoom behavior, record context, split view, list scope, conversation resume/delete, icons, consent, unsupported-table collapse, and the absence of navigation-caused agent activity.

Development loopEdit maintained source → focused check → build → test → upload generated output to development → publish → recreate retained pane if needed → smoke-test.
Do not use production as a styling previewLive form bindings and web-resource publication affect users immediately. Iterate in development and promote only an approved artifact.

9. Package and release an approved change

The repository package is a maintained, importable artifact. Release only an exact package whose complete source and projections are already on GitHub.

  1. Complete the release candidate.

    Update canonical source, regenerate maintained web resources, refresh the Code App build when applicable, and update solution-core/AgentSidecarCore.zip with a Core version higher than the destination installation. The current checked-in package is unmanaged.

  2. Run the complete release gate.

    Confirm the ZIP is readable, projections match canonical source, packaged Code App bytes match dist, and all application and model-driven checks pass.

  3. Commit, review, and push before deployment.
    git status
git add <intended source generated docs and package files>
git commit -m "feat(sidecar): describe the approved change"
git push -u origin feat/your-change

    Open a pull request when contributing. The release owner must ensure the exact release commit is on GitHub before any target-environment import or publication.

  4. Confirm the destination explicitly.
    pac org who --environment https://YOUR-TARGET-ENVIRONMENT.crm.dynamics.com

    Read the returned organization name and URL. Stop if either differs from the intended target.

  5. Import only the pushed package.
    pac solution import \
  --path ./solution-core/AgentSidecarCore.zip \
  --environment https://YOUR-TARGET-ENVIRONMENT.crm.dynamics.com \
  --publish-changes

    Use overwrite options only when the release owner has reviewed the unmanaged-layer impact. Record the commit and package checksum used for the import.

  6. Promote without rebuilding.

    After acceptance, import the exact same reviewed ZIP into the next environment. Do not rebuild, manually alter, or re-export a different package between acceptance and production.

Permanent release ruleEvery intended source, generated, documentation, and package change must be committed and pushed before deployment. Never deploy an uncommitted, unpushed, or locally modified package.
Preserve the combined Core packageThe solution includes a Power Apps Code App. Do not run generic Solution Packager or Git source-integration workflows against the combined Core ZIP. Use the maintained package process and regression tests so the Code App component is not lost.
Current durable artifactsolution-core/AgentSidecarCore.zip is the importable Core package. At publication this guide aligns to 1.0.0.25; inspect solution.xml or repository history rather than assuming this displayed version is always newest.

10. Acceptance checklist

Validate the ordinary model-driven app experience, not only the administration app or a static preview.

Troubleshooting

The pane or old design remains after publishing

Close and recreate the retained pane, then hard-refresh the model-driven app. Confirm the environment contains the current generated web-resource bytes. A retained pane can continue using an older versioned URL after Dataverse is updated.

The configured icon does not match the agent manifest

Agent icons are copied into configuration-owned Dataverse web resources; they are not dynamically linked. Publish the agent, edit Appearance, choose a different icon, reselect the agent logo, save, then recreate or refresh the pane.

The sidecar is healthy but does not appear on a form

Confirm the exact form ID open in the model-driven app. A configuration can target another active main form that the selected app does not use. Edit placement to select the app's actual form, save, and refresh.

A split-view record is treated as a list

Confirm Core 1.0.0.25 or later is installed and recreate the retained pane. The current resolver prefers an open record only when table, record, and form identities all match.

Recent conversations show only a greeting or do not resume

Greeting-only sessions are intentionally omitted. A conversation appears after its first user message. Resume requires both the saved Agents SDK conversation ID and user-owned display-safe activity history.

pac is installed but not found on macOS/Linux

Check $HOME/.dotnet/tools/pac. Ensure $HOME/.dotnet/tools, not a literal ~/.dotnet/tools, is on PATH, then reopen the terminal.

Node, npm, or pnpm is not recognized

Install Node.js LTS, close and reopen the terminal, run corepack enable, and verify pnpm again.

The import succeeds but chat does not connect

Verify the published agent, user access, delegated CopilotStudio.Copilots.Invoke permission, SPA redirect URI, tenant and application IDs, environment ID, agent schema, and Agents SDK connection string. There is no client secret or token-broker configuration in the current runtime.

A package import does not appear as an update

Confirm the solution unique name is AgentSidecarCore, the incoming version is higher, the intended package was pushed, and pac org who reports the expected target.
